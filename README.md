# Sable AutoLoad

Серверный мини-мод для **Minecraft 1.21.1 / NeoForge 21.1.230**, который автоматически держит
сублевелы (sub-level) мода **Sable** — то есть корабли и прочие конструкции Create Aeronautics —
загруженными в заданном радиусе вокруг каждого игрока.

Мод ставится **только на сервер**. Клиентам он не нужен: в метаданных выставлен
`displayTest = "IGNORE_ALL_VERSION"`, поэтому клиенты без мода спокойно подключаются к серверу с ним.

## Что делает

Раз в секунду (каждые 20 тиков) для каждого игрока в сети:

1. Собираются сублевелы, попадающие в бокс радиусом `sableAutoLoadRadius` чанков вокруг игрока.
2. Список сортируется по расстоянию до игрока, берутся ближайшие `sableAutoLoadMax` штук.
3. Каждому из них, если у этого игрока ещё нет нашего тикета, выдаётся force-load тикет
   `sableautoload:auto` (ключ тикета — UUID игрока).

Также:

* **Гистерезис.** Тикет снимается только когда сублевел вышел из *расширенного* бокса —
  радиус `sableAutoLoadRadius + 16` чанков. Это защищает от «мигания» корабля на границе радиуса.
* **Гвард мирогенерации.** Перед выдачей тикета проверяется, что мир под сублевелом уже сгенерирован.
  Проверка идёт через `serverChunkCache.getChunk(x, z, ChunkStatus.FULL, false)` — неблокирующе, без
  генерации. Если чанка нет — сублевел не будится, а на следующем скане просто пересчитается.
  Проверяются: чанк под позицией сублевела (это его holding-чанк, где Sable хранит данные) **и все
  чанки его bounding box** (bbox + 1 блок, как это делает сам Sable). Почему именно footprint:
  получив тикет, `PhysicsChunkTicketManager` вешает ванильные чанк-тикеты на весь bbox сублевела и
  грузит каждый чанк через `level.getChunk(x, z, ChunkStatus.FULL, true)` — блокирующе, с генерацией.
  То есть генерируется ровно footprint корабля, и он обязан быть уже сгенерирован. Это страховка от
  того самого инцидента: массовое пробуждение сублевелов вне преген-зоны генерировало мир в главном
  потоке и валило сервер.
* **Выход игрока.** При `PlayerEvent.PlayerLoggedOutEvent` снимаются все наши тикеты этого игрока
  во всех измерениях, чтобы корабли не оставались загруженными «за ушедшим».
* **Старт сервера.** Тикеты типа `sableautoload:auto` персистентны (лежат в `saved data` мира). Sable
  сам подгружает все сублевелы, у которых есть сохранённые тикеты, ещё в конструкторе уровня
  (`ServerSubLevelContainer#initialize`), то есть **до** серверных событий. Поэтому при
  `ServerStartingEvent` и повторно при `ServerStartedEvent` наш мод проходит по всем измерениям и
  снимает все свои тикеты: сессия начинается с чистого листа, а сохранённые данные очищаются, так что
  на следующем запуске Sable уже ничего «нашего» не подгружает.
* **Лог.** Каждые 30 секунд (`600` тиков) в лог пишется по строке INFO на игрока о том, сколько
  сублевелов за ним держится. Строка пишется только при изменении количества, чтобы не спамить.
  Пропуски кандидатов из-за гварда мирогенерации пишутся на уровне DEBUG.

Важно: контейнеры сублевелов **пер-измерение** (`SubLevelContainer.getContainer(ServerLevel)`),
поэтому игрок в обычном мире никогда не держит загруженными сублевелы Нижнего мира и т.д.

## Геймерулы

| Геймерул | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `sableAutoLoadRadius` | int, чанков | `64` | Радиус, в котором держатся сублевелы. `0` — мод полностью выключен (все свои тикеты снимаются). |
| `sableAutoLoadMax` | int | `8` | Максимум сублевелов, одновременно удерживаемых за одним игроком. `0` — новые тикеты не выдаются (уже выданные продолжают действовать, пока сублевел не выйдет из радиуса). |

Примеры:

```
/gamerule sableAutoLoadRadius 96
/gamerule sableAutoLoadMax 12
/gamerule sableAutoLoadRadius 0
```

## Сборка

Требуется JDK 21 (`JAVA_HOME=/usr/lib/jvm/java-21-openjdk`; системная Java 27 не подходит).

```bash
cd /home/peter/p/sable-autoload
JAVA_HOME=/usr/lib/jvm/java-21-openjdk ./gradlew build
```

Результат: `build/libs/sableautoload-1.0.0.jar`.

Первый запуск сборки скачивает NeoForge/Minecraft-артефакты и декомпилирует Minecraft (несколько
минут), дальше всё берётся из кэша `~/.gradle/caches/neoformruntime`.

### Зависимости на этапе компиляции

Всё лежит в `libs/` и подключается как `compileOnly` (в итоговый jar не попадает):

* `sable-neoforge-1.21.1-2.0.6.jar` — API Sable;
* `sable-companion-common-1.21.1-1.6.0.jar` — `dev.ryanhcode.sable.companion.math`
  (`BoundingBox3d`, `Pose3dc`); в Sable подключён через Jar-in-Jar (`META-INF/jarjar/`);
* `veil-neoforge-1.21.1-4.3.2.jar` — `foundry.veil`, тоже Jar-in-Jar внутри Sable; нужен только
  потому, что классы Sable ссылаются на него в сигнатурах.

## Установка

1. Скопировать `build/libs/sableautoload-1.0.0.jar` в `mods/` сервера.
2. Убедиться, что на сервере есть Sable (мод объявляет его обязательной зависимостью).
3. Перезапустить сервер. В логе появится `Sable AutoLoad: initialized`.

## Известные ограничения

* Сканирование идёт по **загруженным** сублевелам (`queryIntersecting` возвращает то, что уже есть в
  контейнере измерения). Сублевел, чей чанк вообще не загружен, разбудить этим API нельзя — Sable даёт
  `addForceLoadTicket` только для живого `ServerSubLevel`. Практически это значит, что мод удерживает
  загруженными корабли в радиусе, а не «вытаскивает с того света» те, что лежат на диске далеко.
* Гвард мирогенерации проверяется в момент выдачи тикета. Если уже загруженный (затикетенный) корабль
  сам улетит в неcгенерированную зону, чанки под ним сгенерирует уже сам Sable — это его поведение, и
  предотвратить его без миксинов нельзя. При полностью прегенерённом мире вопрос не возникает.
* Тикеты, чей сублевел не загружен в данный момент, снять нельзя: в API Sable удаление идёт только по
  живому `ServerSubLevel` (`removeForceLoadTicket(ServerSubLevel, ...)`). При штатном завершении работы
  сервера тикеты всё равно живут в `saved data` и снимаются на старте (см. выше), поэтому «мусорных»
  тикетов не накапливается.

## Структура

```
src/main/java/net/sableautoload/
  SableAutoLoad.java            — точка входа @Mod, регистрация геймерул и типа тикета
  SableAutoLoadGameRules.java   — геймерулы sableAutoLoadRadius / sableAutoLoadMax
  AutoLoadTickets.java          — тип тикета sableautoload:auto (ключ — UUID игрока)
  AutoLoadManager.java          — сканы, выдача/снятие тикетов, гвард мирогенерации, логи
```
